# 页边 · Margin Reader
A private website for reading with explanations in the margin. **Not for public.**
Generated by GPT-6 Astra.

保留绿色阅读排版、手机上下分屏/词卡横向吸附、人物别称共用词卡、全文搜索、阅读状态、个人笔记、备份及可定制生成说明。

新增：阅读位置自动保存；按最后更新时间排序（阅读与导入都会更新）；每篇文章有 `/read/文章编号/` 路径，支持前进、后退、刷新和直接访问。

## 先了解保存与公开范围

- 普通个人 GitHub Pages 网站是公开的，即使使用私人仓库发布，也不等于网站私有。
- `articles/` 中提交并发布的文章可被所有访问者读取。包内没有你的私人文章。
- 网页“导入文章”保存到当前浏览器的 IndexedDB，不会上传到 GitHub；阅读位置、状态、笔记也保存在当前浏览器。不同设备不自动同步。
- 浏览器关闭后通常保留这些数据，但清理网站数据、无痕模式、浏览器存储回收会造成丢失。请使用“备份”导出 JSON，备份保存在仓库外。
- 本版没有登录系统，不要把 GitHub Token 或 API 密钥放入网页。
- 页面删除只影响当前浏览器。要从仓库/公共站点删除文章，需要删除对应 `articles/*.json`，提交并重新部署；Git 历史可能仍保留旧内容。

## 文件管理

| 路径 | 用途 | 是否手工维护 |
|---|---|---|
| `articles/` | 全部准备发布的文章分析 JSON，每篇一个文件 | 是 |
| `src/App.tsx` | 页面、路径导航、阅读交互和自动保存 | 修改功能时 |
| `src/styles.css` | 网站排版和颜色 | 修改样式时 |
| `src/reading.ts` | 数据格式、人物匹配、生成说明 | 修改规范时 |
| `src/storage.ts` | 浏览器保存与仓库文章合并 | 修改存储时 |
| `scripts/add.mjs` | 将文章或备份拆分到 `articles/` | 不必修改 |
| `scripts/articles.mjs` | 校验文章并生成目录 | 不必修改 |
| `scripts/routes.mjs` | 生成独立路径的 HTML 页面和 404 回退 | 不必修改 |
| `examples/reading-example.json` | JSON 格式示例，不会自动发布为文章 | 参考 |
| `.github/workflows/pages.yml` | push 后自动部署 | 通常不改 |
| `dist/` | 自动生成的部署结果，已忽略 | 不要手改 |

## 第一次运行

安装 Node.js 22（至少 22.13），将文件夹用 VS Code 打开，在该文件夹终端运行：

```bash
npm ci
npm run dev
```

打开终端显示的本地网址。不要直接双击 `index.html`；文章加载和本地存储需要 HTTP 服务。

检查与构建：

```bash
npm test
npm run build
npm run preview
```

## 发布到 GitHub Pages

1. 创建自己的 GitHub 仓库，例如 `margin-reader`。先确认哪些文章愿意公开。
2. 将本目录内容放在仓库根目录，包含 `.github/workflows/pages.yml`。不要上传 `node_modules/`、`dist/`、私人备份或密钥。macOS Finder 默认隐藏 `.github`，使用 VS Code 或 Git 提交可避免遗漏。
3. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
4. 默认分支使用 `main`；如果使用其他分支，修改工作流中 `branches`。
5. push 后，在 **Actions → Publish Margin Reader** 查看部署结果。网址以部署成功时 GitHub 返回的地址为准。

通常项目网址为 `https://用户名.github.io/margin-reader/`。工作流会自动使用 GitHub Pages 提供的路径前缀，既支持普通项目路径，也支持 `用户名.github.io` 根站点；如需自定义域名，应在 GitHub Pages 设置域名后重新部署。

已有关联 GitHub 仓库时：

```bash
git add -A
git commit -m "Set up Margin Reader"
git push
```

## 每次添加文章

方式 A：将 GPT 生成的单篇 JSON 放进 `articles/`，文件名可采用 `2026-11-02-article-topic.json`。提交后由 Actions 自动校验、生成目录和网页。

方式 B（自动整理，支持整库备份）：

```bash
npm run add -- "/你的路径/文章分析.json"
```

多份文件：

```bash
npm run add -- "/你的路径/第一篇.json" "/你的路径/第二篇.json"
```

然后：

```bash
git add articles
git commit -m "Add reading articles"
git push
```

整理命令使用文章 ID 作为文件名，重复 ID 会跳过；修改已有文章可直接编辑对应文件并保持 ID 不变。备份拆分时会去掉个人笔记、阅读状态和位置，避免将这些内容发布到站点。但**原始备份本身不能提交到公共仓库**。

网页导入只存入当前浏览器。如需让它成为仓库文章：导出本文，然后用上述命令添加。浏览器不能在没有额外认证服务的情况下直接修改你的 GitHub 文件夹。

## 从现有 Sites 迁移

1. 在原私人 Sites 点击顶部“备份”，下载全部文章及阅读记录。
2. 在 GitHub Pages 版本点击“导入文章”，上传备份并确认，可在当前设备恢复文章、位置、状态和笔记。
3. 如果只想自己阅读，保持浏览器导入模式即可；这些文章不会随站点公开发布。
4. 若要将文章集中纳入仓库，用 `npm run add -- "/备份路径/备份.json"` 拆分，再审阅 `articles/` 后提交。源代码包不包含原 Sites 后端数据。
5. 仓库文章和浏览器备份中相同 ID 的条目视为同一篇。为保留个人记录，推荐先在网页恢复备份，再把文章加入仓库；重复网页导入会跳过，不覆盖现有记录。

## 路径与前进/后退

- 主页：`/仓库名/`
- 导入：`/仓库名/import/`
- 文章：`/仓库名/read/文章ID/`

仓库文章构建时生成真实 HTML 路径，所以直接打开/刷新不依赖一次首页访问。
仅在浏览器导入的文章无法在构建时预先生成 HTML：直接打开该路径时会由 `404.html` 回到应用并恢复原路径（有 JavaScript 时生效）。其他设备如果没有导入该文章，会显示“找不到这篇文章”。新部署的文章首次加载需要网络。

## 自动保存与更新时间

- 滚动时立即记录本地位置，停顿约 0.8 秒写入文章记录；切换页面或标签页时也会尝试保存。突然关闭时，下次同一浏览器打开会使用最近的本地位置恢复。
- 打开文章即视为一次阅读活动；滚动、导入、修改状态或保存笔记都会更新“最后更新时间”。
- 默认“最近更新优先”，也可选择“最早更新优先”或按添加时间正/倒序。
- GitHub 仓库文章的更新日期来自该文件最后一次 Git 提交；浏览器中的阅读更新时间只影响当前浏览器。
- 完整备份包含阅读记录。跨设备时手动导出/导入；没有自动云同步。

## 文档与已知限制

GitHub Pages 是静态托管，现有 Sites 的 R2 后端和登录服务不随本包迁移；当前版本采用浏览器保存，无后台 API 费用。

页面阅读位置按原文/译文滚动区域的比例保存。改变窗口尺寸或文章内容后，恢复位置可能与原来的具体句子略有偏差。
